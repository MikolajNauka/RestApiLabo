1. Cel zadania i architektura systemu

Celem niniejszego zadania było praktyczne zaimplementowanie komunikacji między dwoma niezależnymi mikroserwisami w architekturze rozproszonej przy użyciu protokołu REST (Representational State Transfer) przez HTTP. System realizuje wspólny proces biznesowy: Serwis Magazynowy udostępnia informacje o stanach magazynowych towarów, lecz przed udzieleniem odpowiedzi synchronicznie odpytuje Serwis Produktów o potwierdzenie istnienia danego produktu.

Rysunek 1: Przepływ synchronicznej komunikacji HTTP/REST między mikroserwisami.

3. Implementacja technologiczna

Do realizacji zadania wybrano język Python 3 oraz nowoczesny, asynchroniczny framework FastAPI uruchamiany na serwerze Uvicorn:

  • Serwis Produktów: Przechowuje mockowaną kolekcję encji Product w pamięci RAM. Udostępnia endpoint GET /products/{id}, weryfikuje obecność klucza w słowniku i zwraca model JSON lub rzuca wyjątek HTTPException(status_code=404).
  • Serwis Magazynowy: Używa biblioteki requests z ustawionym limitem czasu (timeout) do wykonania zapytania GET do Serwisu Produktów pod adresem http://127.0.0.1:8001/products/{product_id}. Jeśli serwis zwróci status 200, Serwis Magazynowy odczytuje stan magazynowy z bazy STOCK_DB. Jeśli zwróci kod 404, Serwis Magazynowy natychmiast propaguje błąd 404 do klienta. Dodatkowo zaimplementowano obsługę błędu 503 Service Unavailable w sytuacji braku łączności sieciowej.

5. Podsumowanie i wnioski

Główne wnioski z realizacji zadania:
  1. Separacja odpowiedzialności (Separation of Concerns): Podział domeny biznesowej na katalog produktów i stan magazynowy pozwala na niezależny rozwój, skalowanie i wdrażanie każdego z modułów.
  2. Standaryzacja protokołu REST: Wykorzystanie kodów stanu HTTP (200, 404, 503) oraz formatu JSON gwarantuje jednoznaczność interpretacji odpowiedzi przez systemy integrujące.
  3. Odporność na błędy: Kluczowym elementem systemów rozproszonych jest poprawna obsługa sytuacji awaryjnych (propagacja kodów błędów oraz obsługa niedostępności serwisów zależnych z użyciem mechanizmu timeout).
